### HTTP 适配器异常处理 + 响应格式统一改造

改造了 `src/adapter/inbound/http/` 下所有 handler 的异常处理和响应格式：

### 改动文件
- `adapters.rs` — ApiSuccess/ApiError 重构 + 全部 handler 改造
- `route_adapter.rs` — debug_routes_handler 使用 ApiSuccess
- `routes/traces.rs` — 错误响应字段统一（message → error, code）
- `routes/sessions.rs` — 同上

### 具体改动
1. **ApiSuccess<T: Serialize> 泛型化** — `IntoResponse` 适用于任意 `T: Serialize`
2. **ApiError 增强** — 增加 `details` 可选字段 + 构造函数 `internal()`, `not_found()`, `bad_request()`, `with_detail()`
3. **所有 handler 返回 `impl IntoResponse`**（不再返回裸 `Response`）
4. **if response.success → ApiSuccess::ok() / else → ApiError::internal()** 模式统一，消除了 4 处重复的 `(StatusCode, AxumJson(json!({...})))` 手动拼 JSON
5. **响应字段统一**：
   - 成功：`{ "success": true, "data": { ... } }`（旧 chat 用 `"response"`，已统一为 `"output"`）
   - 错误：`{ "success": false, "error": "...", "code": 404 }`（旧用 `"message"`，已统一为 `"error"`）
6. **session_id 通过 ApiError::with_detail() 保留在错误响应的 details 字段**

## 修复 Makefile Python 脚本适配 ApiSuccess 嵌套结构

`ApiSuccess` 把业务数据包在 `{"success":true,"data":{...}}` 里，但 Makefile 格式化脚本从根级别读字段（如 `d.get('output')`），导致 orch-run 等命令显示空输出。
修复：每个格式化分支加 `dd = d.get('data', d)` 从 data 字段下取值。

## 修复 chain 信息在 trace 记录中丢失

`chain`（调度链/策略名称）和 `expert_chain`（专家执行链）在 trace 持久化记录中完全丢失。
根因：`TraceHandle` 无 chain 字段；`finalize_trace` 不收 chain 参数；`get_trace` 硬编码 `"chain_name": null`。
修复：
- `observer.rs` — TraceHandle 增加 chain_name/expert_chain 字段及访问器；complete_success 日志输出 chain 信息
- `trace_decorator.rs` — finalize_trace 增加 chain 参数；orchestrate 路径传入 resp.chain.first() 和 resp.expert_chain；stream 路径从 Done.meta 提取
- `observer_adapters.rs` — list_summaries/get_trace 使用真实 chain 数据
